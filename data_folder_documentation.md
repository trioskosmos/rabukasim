# Data Folder Documentation

## Current Data Pipeline (from README.md)

The ability pipeline uses three files with different roles:

1. **`ability_frame_source.json`** - Authored sparse ability source (what the compiler reads)
   - Generated by: Manual editing (author-editable)
2. **`ability_runtime_index.json`** - Machine-facing runtime frame index used by Rust
   - Generated by: Build pipeline (compiler)
3. **`ability_frame_index.json`** - Human-facing review index
   - Generated by: Build pipeline (compiler)
4. **`cards_compiled.json`** - Compiled runtime card database
   - Generated by: Build pipeline (compiler)
5. **`metadata.json`** - Opcode IDs and packed layout schema
   - Generated by: Manual editing (author-editable)

## Key Files in Data Folder

### Source Files (Author-Editable)
- **`ability_frame_source.json`** - Main authored source with frames, triggers, card references
- **`ability_frame_source.compact.json`** - Compact version
- **`ability_frame_source.simple.md`** - Simplified markdown version

### Semantic Extraction Files (My Work)
- **`ability_semantic_dump.json`** - Semantic extraction output from `engine/compiler/semantic_simple.py`
  - Generated by: `engine/compiler/semantic_simple.py` → `extract_semantic_simple()`
  - Contains 612 abilities with semantic structure
  - Has trigger_id, trigger, primary_text_jp, source_ability_texts
  - No frames - only semantic extraction

### Metadata Files
- **`metadata.json`** - Opcode IDs, trigger IDs, target IDs, packed layout schema
  - `triggers`: NONE=0, ON_PLAY=1, ON_LIVE_START=2, etc.
  - `opcodes`: RETURN=1, DRAW=10, ADD_BLADES=11, etc.
  - `targets`: SELF=0, PLAYER=1, OPPONENT=2, etc.

### Runtime Files (Generated)
- **`ability_runtime_entrypoints.json`** - Runtime entry points
  - Generated by: Build pipeline (compiler)
- **`ability_runtime_index.json`** - Machine-facing runtime frame index
  - Generated by: Build pipeline (compiler)
  - Used by: `engine_rust_src/src/core/logic/card_db.rs` (Rust runtime loader)
- **`ability_frame_index.json`** - Human-facing review index
  - Generated by: Build pipeline (compiler)
- **`cards_compiled.json`** - Compiled runtime card database
  - Generated by: Build pipeline (compiler)
  - Mirrored to: `engine/data/cards_compiled.json` (engine-side)
  - Mirrored to: `launcher/static_content/data/cards_compiled.json` (launcher-side)

### Archive Files
- **`archive/`** - Contains old versions and backups

## What We Have vs What We Need

### Current State:
- **`ability_semantic_dump.json`**: Semantic extraction (triggers, actions, conditions, choices, sequences, costs)
- **`ability_frame_source.json`**: Complete frame-based format with opcodes, params, slots, verification

### The Gap:
The semantic extraction produces:
- `when`: trigger name
- `if`: condition
- `then`: array of action objects (type, matched text)
- `with`: metadata (count, zones, card_types, groups, optional)
- `choices`: choice structure
- `sequences`: sequential structure
- `costs`: cost structure

The frame source format needs:
- `trigger_id`: numeric ID from metadata
- `trigger`: string name
- `frames`: array of frame objects with:
  - `op`: opcode string (from metadata)
  - `frame_index`: order
  - `value`: numeric value
  - `params`: raw_cond, raw_effect, FILTER, EQ, etc.
  - `attr`: is_optional, once_per_turn, target_player, zone_mask
  - `slot`: target_slot, source_zone, dest_zone

## Transformation Strategy

We need to transform semantic extraction results into frame format:

1. **Map trigger names to trigger_ids** using `metadata.json`
2. **Map action types to opcodes** using `metadata.json`
3. **Extract values from matched text** (counts, zones, card types)
4. **Build frame objects** with correct structure
5. **Preserve order** using frame_index
6. **Handle special structures**:
   - Choices: Use SELECT_MODE or similar
   - Costs: Use PAY_ENERGY or similar
   - Sequences: Use JUMP or frame ordering
7. **Include metadata** from `with` field into `attr` and `params`
