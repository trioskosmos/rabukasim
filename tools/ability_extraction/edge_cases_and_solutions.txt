# Edge Cases and Solutions for Ability Parsing

## Edge Case 1: Quotes Have Two Different Uses

**Problem:** 「 」 is used for both character names and nested abilities
- Character names (73 cases): 「上原歩夢」, 「澁谷かのん」 - short, no icons
- Nested abilities (41 cases): 「{{jyouji.png|常時}}ライブの合計スコアを+１する。」 - contains icons/verbs

**Current behavior:** Treats all quotes identically, splits on 「 and 」 as separate clauses
**Impact:** The 30-clause ability has nested ability split into 5 fragments instead of 1 clause

**Solution:**
```python
def parse_quote_content(content: str) -> str:
    """
    Determine if quoted content is a character name or nested ability.
    Returns: 'character_name' or 'nested_ability'
    """
    # Character name: short (2-4 chars), no spaces, no icons
    if len(content) <= 4 and '{{' not in content and ' ' not in content:
        return 'character_name'
    # Nested ability: contains icons or verbs
    elif '{{' in content or any(verb in content for verb in ['する', '得る', '引く']):
        return 'nested_ability'
    else:
        return 'character_name'  # default
```

**Implementation:**
- When encountering 「, peek ahead to the closing 」
- Extract content and classify it
- If character name: keep as selection clause
- If nested ability: extract as single clause, don't split internal delimiters

## Edge Case 2: Commas Have Two Different Uses

**Problem:** 、 is used for both clause separation and list item separation
- Clause separator: "カードを1枚引き、手札を1枚控え室に置く" (should split)
- List item separator: "[桃ブレード]、[赤ブレード]、[黄ブレード]のうち" (should NOT split)

**Current behavior:** Splits on ALL commas
**Impact:** The 30-clause ability has 6 blade colors + 6 commas = 12 clauses instead of 1 list clause

**Solution:**
```python
list_indicators = ['か', 'と', 'または', 'いずれか', 'のうち', '以外']
list_depth = 0

def should_split_on_comma(context: str, position: int) -> bool:
    """
    Determine if comma should split based on context.
    """
    # Don't split if in list context
    if list_depth > 0:
        return False
    
    # Don't split if comma is between repeated icons
    if is_between_repeated_icons(context, position):
        return False
    
    # Otherwise, split
    return True

def update_list_depth(char: str, next_char: str):
    """
    Track list depth based on indicators.
    """
    global list_depth
    if char in list_indicators:
        # Look ahead to see if this starts a list
        if next_char == '[' or next_char in list_indicators or next_char == '、':
            list_depth += 1
```

**Implementation:**
- Track list context with `list_depth` counter
- Increment when seeing list indicators followed by placeholder or another indicator
- Decrement after clause boundaries (。, ：)
- Only split on comma when `list_depth == 0`

## Edge Case 3: Parenthetical Notes as Metadata

**Problem:** （ ） contains clarifications/notes, not main effect clauses
- Example: "（ウェイト状態のメンバーが持つ{{icon_blade.png|ブレード}}は、エールで公開する枚数を増やさない。）"
- Example: "（この能力はセンターエリアに登場している場合のみ起動できる。）"

**Current behavior:** Splits on （ and ） as separate clauses
**Impact:** Parenthetical notes appear as separate clauses in the analysis

**Solution:**
```python
def extract_parenthetical_notes(template: str) -> tuple[str, list[str]]:
    """
    Extract parenthetical notes and return cleaned template + notes.
    """
    notes = []
    cleaned = template
    while '（' in cleaned and '）' in cleaned:
        start = cleaned.find('（')
        end = cleaned.find('）', start)
        if end != -1:
            note = cleaned[start:end+1]
            notes.append(note)
            cleaned = cleaned[:start] + cleaned[end+1:]
    return cleaned, notes
```

**Implementation:**
- Extract all parenthetical notes before main parsing
- Store as metadata/annotations attached to the ability
- Don't include in clause position analysis
- Display separately in output

## Edge Case 5: Nested References

**Problem:** Clauses reference previous clause outputs using specific phrases
- "その中から" (from among them)
- "残り" (the rest)
- "これにより" (by this)
- "それら" (those)

**Current behavior:** Not tracked explicitly
**Impact:** No structural understanding of clause dependencies

**Solution:**
```python
reference_phrases = ['その中から', '残り', 'これにより', 'それら', 'その後']

def identify_references(clause: str) -> list[str]:
    """
    Identify if clause contains reference phrases.
    """
    found = []
    for phrase in reference_phrases:
        if phrase in clause:
            found.append(phrase)
    return found
```

**Implementation:**
- Track which clauses contain reference phrases
- Build dependency graph between clauses
- Display in analysis: "Clause 3 references Clause 2 via 'その中から'"

## Edge Case 6: Empty Clauses from Delimiter Combinations

**Problem:** Consecutive delimiters create empty clauses
- Example: " ： " creates ['', '：', ''] instead of just '：'
- Example: " 。）" creates ['。', ')', ''] instead of ['。', ')']

**Current behavior:** Includes empty clauses in position analysis
**Impact:** Inflates clause counts (30 positions includes many empty clauses)

**Solution:**
```python
def filter_empty_clauses(clauses: list[str]) -> list[str]:
    """
    Remove empty clauses unless they're meaningful.
    """
    filtered = []
    for clause in clauses:
        if clause.strip() or clause in ['：', '。', '、', '（', '）', '「', '」']:
            filtered.append(clause)
    return filtered
```

**Implementation:**
- Filter out empty strings after parsing
- Keep delimiter-only clauses (they mark structure)
- This would reduce the 30-clause ability to ~20 clauses

## Edge Case 7: Conditional Clauses

**Problem:** Conditional phrases create nested structures
- "場合" (in case of)
- "かぎり" (as long as)
- "時" (when)

**Current behavior:** Treated as flat clauses
**Impact:** No understanding of conditional nesting

**Solution:**
```python
conditional_markers = ['場合', 'かぎり', '時']

def identify_conditionals(clause: str) -> str:
    """
    Identify if clause is a conditional and what type.
    """
    for marker in conditional_markers:
        if marker in clause:
            return marker
    return None
```

**Implementation:**
- Mark clauses that start or end with conditional markers
- Build conditional tree structure
- Display as: "Conditional (場合): [clause content] → Effect: [next clause]"

## Proposed Grammar-Based Parser Architecture

### Pass 1: Preprocessing
```python
def preprocess(template: str) -> tuple[str, list[str]]:
    """
    Extract metadata and clean template.
    """
    # Extract parenthetical notes
    cleaned, notes = extract_parenthetical_notes(template)
    
    # Extract and classify quotes
    cleaned = process_quotes_contextually(cleaned)
    
    return cleaned, notes
```

### Pass 2: Context-Aware Parsing
```python
def parse_with_context(template: str) -> list[dict]:
    """
    Parse template with context awareness.
    """
    clauses = []
    current = ""
    list_depth = 0
    in_quote = False
    quote_type = None
    
    i = 0
    while i < len(template):
        char = template[i]
        
        # Track list context
        if char in list_indicators:
            if i + 1 < len(template):
                next_char = template[i + 1]
                if next_char == '[' or next_char in list_indicators:
                    list_depth += 1
        
        # Track quote context
        if char == '「':
            in_quote = True
            # Peek ahead to classify quote
            quote_end = template.find('」', i)
            if quote_end != -1:
                content = template[i+1:quote_end]
                quote_type = parse_quote_content(content)
        elif char == '」':
            in_quote = False
            quote_type = None
        
        # Handle delimiters based on context
        if char == '、':
            if list_depth > 0 or in_quote:
                # Don't split - part of list or quote
                current += char
            else:
                # Split - clause separator
                if current:
                    clauses.append({'text': current, 'type': 'clause'})
                clauses.append({'text': char, 'type': 'delimiter'})
                current = ''
        elif char in ['：', '。']:
            # Always split
            if current:
                clauses.append({'text': current, 'type': 'clause'})
            clauses.append({'text': char, 'type': 'delimiter'})
            current = ''
            # Reset list depth after major delimiters
            list_depth = 0
        else:
            current += char
        
        i += 1
    
    if current:
        clauses.append({'text': current, 'type': 'clause'})
    
    return clauses
```

### Pass 3: Post-Processing
```python
def postprocess(clauses: list[dict]) -> list[dict]:
    """
    Filter empty clauses and add metadata.
    """
    filtered = []
    for clause in clauses:
        # Filter empty non-delimiter clauses
        if clause['type'] == 'clause' and not clause['text'].strip():
            continue
        
        # Add reference tracking
        refs = identify_references(clause['text'])
        if refs:
            clause['references'] = refs
        
        # Add conditional tracking
        cond = identify_conditionals(clause['text'])
        if cond:
            clause['conditional'] = cond
        
        filtered.append(clause)
    
    return filtered
```

### Expected Results

**Before (current delimiter-based):**
- 30-clause ability splits into 30 positions
- Many empty clauses
- Nested ability split into 5 fragments
- List of 6 items split into 12 clauses

**After (grammar-based):**
- Same ability splits into ~10 clauses
- No empty clauses
- Nested ability as 1 clause
- List of 6 items as 1 clause
- Conditional structure preserved
- References tracked
- Parenthetical notes as metadata
