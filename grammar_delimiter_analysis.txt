# Grammar Delimiter Analysis

## Delimiter Usage Statistics

| Delimiter | Name | Count | Usage |
|-----------|------|-------|-------|
| ： | colon | 538 | Separates cost from effect |
| 、 | comma | 1347 | Separates clauses and list items |
| 。 | period | 1345 | Ends sentences |
| （ | open_paren | 56 | Starts parenthetical notes |
| ） | close_paren | 56 | Ends parenthetical notes |
| 「 | open_quote | 118 | Starts quoted content |
| 」 | close_quote | 118 | Ends quoted content |

## Key Finding: Quotes Have Two Different Uses

The 「 」 delimiter is used for TWO different purposes:

### 1. Character Names (73 cases)
- Examples: 「上原歩夢」, 「澁谷かのん」, 「日野下花帆」, 「米女メイ」, 「唐可可」
- Pattern: Short text (2-4 characters), no spaces, no icons
- Usage: Selecting specific characters from a list
- Example: `自分のステージに「澁谷かのん」か「日野下花帆」か「安養寺姫芽」がいるかぎり`

### 2. Nested Abilities (41 cases)
- Examples: 「{{jyouji.png|常時}}ライブの合計スコアを+１する。」
- Pattern: Contains icons ({{...}}), verbs, periods
- Usage: Quoting complete abilities to be "gained" as effects
- Example: `さらにライブ終了時まで、「{{jyouji.png|常時}}ライブの合計スコアを+１する。」を得る。`

## Problem with Current Approach

The current delimiter-based parser treats ALL quotes identically:
- Splits on 「 and 」 as separate clauses
- Cannot distinguish between character names and nested abilities
- Results in incorrect parsing for the 30-clause ability

## Parenthetical Notes （ ）

- 56 total occurrences
- Consistently used for metadata/clarifications
- Examples:
  - `（ウェイト状態のメンバーが持つ{{icon_blade.png|ブレード}}は、エールで公開する枚数を増やさない。）`
  - `（この能力はセンターエリアに登場している場合のみ起動できる。）`
  - `（手札のこのカードもこの効果で控え室に置ける。）`
- These should be treated as annotations, not main clauses

## Colon (：) Patterns

- 538 total occurrences
- **Before colon**: Costs
  - 87x: `...nergy.png|E}}支払ってもよい`
  - 82x: `...|登場}}手札を1枚控え室に置いてもよい`
  - 52x: `...}このメンバーをステージから控え室に置く`
  - 44x: `...{icon_energy.png|E}}`
- **After colon**: Effects
  - 35x: `自分のデッキの上からカードを5枚見る。そ...`
  - 34x: `自分の控え室からライブカードを1枚手札に...`
  - 28x: `ライブ終了時まで、{{icon_blad...`
  - 26x: `自分のデッキの上からカードを3枚見る。そ...`

## Comma (、) Patterns

- 1347 total occurrences
- Used for TWO different purposes:
  1. Separating action clauses (should split)
  2. Separating list items (should NOT split)
- List indicators: `か`, `と`, `または`, `いずれか`, `のうち`
- The 30-clause ability has commas separating 6 blade colors that should be ONE list

## Recommendations

### Grammar-Based Parsing Approach

1. **Treat quotes contextually**:
   - If quoted content is short + no icons → character name (selection)
   - If quoted content has icons/verbs → nested ability
   - Parse them differently in the AST

2. **Handle list indicators**:
   - Track context when seeing `か`, `と`, `または`, `のうち`
   - Don't split on commas within list contexts
   - Example: `A、B、Cのうち` = one list clause, not 5 clauses

3. **Parenthetical notes as metadata**:
   - Extract as annotations attached to main clauses
   - Don't treat as separate clauses in main flow

4. **Colon as structural delimiter**:
   - Always split on colon (cost/effect separator)
   - This is consistent across all 538 occurrences

5. **Period as sentence boundary**:
   - Always split on period (sentence end)
   - This is consistent across all 1345 occurrences

This would reduce the 30-clause ability to ~10 clauses by:
- Consolidating 6 blade colors + 6 commas into 1 list clause
- Treating nested ability in quotes as 1 clause instead of 5 fragments
- Removing empty clauses from delimiter combinations
